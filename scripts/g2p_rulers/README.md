# G2P rulers — 给「音节切在哪」造的外部判据

**这个目录是发明,不是脚手架。** 它存在的理由写在队列的「判据能力」表里:
de / fr / es / it 四门语言**结构性地没有耳裁**(用户:「我压根听不懂」),而社区侧也不涉及,
所以这几门语言的每一条切分结论**只能建立在仪器上**。S111 之前那把仪器并不存在 ——
§C24 整轮是靠「读成文规范 + 手查六个词」立起来的。

## 新造一把尺子时的硬规矩(全部是付过学费的)

1. **机械抓取,不许让 agent 读页面再转述。** 抓 wikitext 原文 → 落盘缓存 → 正则抽。
   (S98 的自证陷阱形状:模型转述一遍,证据就变成了模型的意见。)
2. **「查过但没有」也要缓存。** 覆盖率必须是可复算的事实,而不是「我没找到」。
   ⇒ 判「问过没有」用 `title in cache`,**不是** `cache.get(title)` —— 后者对两种情况返回同一个 None。
3. **对照组必须预注册**:期望答案在跑之前写死,每条带「凭什么它不容争辩」。
   ⛔ 答案没人知道的样本(音译名)不许进对照组,那是自证。
4. **对照组必须包含【这把尺子最可能出错的那一类】**。S111 的对照组 24 条**没有一条**能触发
   它后来出错的模式,于是「20 一致 / 0 相反」完全没拦住那个错误。
5. **取样/选点规则里绝不能出现被测变量。** S111 用「与词典音素对得上」去挑位点,
   而假设正是「那个音素的清浊决定答案」⇒ 反面证据被静默变成沉默,输出一个漂亮的 `0 refuted`。
   **机械做法:先算「如果结论是反的,这个测量会返回什么」,算不出来就不许写「证实」。**
6. **一把判据必须与「什么都不做」的基线比。** 报准确率之前先报基线准确率,并**单独报少数类**
   (= 你真正要检出的那一类)。S112 的形状判据留一 53:1,而常数预测器逐键相同。
7. **工装解析生产常量、零手抄**;而「改前/改后」两臂**至少有一臂来自版本控制**
   (`C24_G2P_REV=<commit>`),否则你一改生产,对照臂就跟着你一起变。
8. **动共享缓存前先快照。** 补抓会让上一轮的数再也复现不出来 —— 那不是退化,但闸会红得像退化。

## 结论的引用纪律

- **沉默 ≠ 支持**;而「没问过」连沉默都不算。三档要分开报。
- **一个信号「从没出过错」可能是「从没被考过」**。凡结论由某个信号独家支撑,必须写明是哪一个。
- 数字要带**口径**(钉在哪个 commit 面上 / 哪个缓存状态),两个面的数不许混着引用。
