# range rulers — 给「音域扩展的逆变换」造的外部判据

**这个目录存在的理由是一次实付四个月的事故。**

2026-07-26,我们把逆变换从 TD-PSOLA 换成 Signalsmith,理由是「PSOLA 有些地方脏」。
守那份 PSOLA 的闸是 `psola_ab.rs`,而它**只量音高**。
仓里同时躺着一条实测:**praat 的 TD-PSOLA 在本仓素材上透明**(ΔHNR −0.12~+2.68 dB),
而**我们那份 Rust 实现掉 5.15~8.57 dB** —— 也就是说,当年被判死的是**我们自己写坏的那一个**,
不是这个算法。判据够不着症状轴 ⇒ 实现缺陷结构上溜过去 ⇒ **一个正确的方向被关了四个月**
(S145 定案,用户 2026-08-14 亲自提出这条规矩:「凡引用『我们试过 X,X 输了』,
先问输的是**算法**还是**我们的实现**」)。

⇒ 这里的每一把尺子,都是为了让下一次的「换引擎」有一个**够得着症状轴**的判据。

## 四把尺子 · 各自答什么 / 答不了什么

| | 尺子 | 答 | ⛔ 答不了(已登记的盲区) |
|---|---|---|---|
| ① | `envelope_shift` | 共振峰包络被搬了几个半音 | 哪个更好听;**OLA 相位错没错**(PSOLA 由构造保持共振峰 ⇒ 哪怕嗡嗡作响它照样读 ~0) |
| ② | `transient_flux` | 2-11 kHz 瞬态(塞音爆发)有没有被抹平 | **WORLD 塌清塞音它看不见**(实测只读 −0.37 dB,而对人为抹平能读 −33 dB);⛔ 跨共振峰策略比较时读数被混淆 |
| ③ | `hnr` | 谐噪比掉了多少 = 重合成脏不脏 | 共振峰位置对不对 |
| ④ | `f0_error` | 音高准不准 | **音色 / 纹理 / 响度全都不管** —— 2026-07 就是它放行的 |

⭐ **③ 是本工装相对队列 §E13 笔 0 原始规格新加的那一把**,理由就在上面:
①② **都看不见**「我们把 PSOLA 写坏了」这一形状,而 ③ 看得见 —— 它就是当年区分开
praat 与我们那份坏实现的那把尺子。

⛔ **四把必须一起读。** 任何一把单独当判据都有已登记的盲区(`registry.json` 的
`known_blind_spots`)。而 ④ 永远不许单独出现在任何验收里。

## 参照臂(`arms.py`)

* `praat_psola` —— praat 的 TD-PSOLA(Manipulation + PitchTier ×ratio + overlap-add)。
  **这是笔 1 的对拍靶子**:一个已知透明的答案。
* `world_resynth` —— WORLD 源-滤波重合成。⛔ **已在 S145 出局**(塌清塞音,用户两次耳判)。
  留着只有一个用途:**当已登记盲区的活样本** —— 一个「仪器说没事、耳朵说完蛋」的实例。

## 怎么用

```powershell
# 解释器必须是 training/.venv(pyworld / praat-parselmouth / soundfile / scipy 都在里面)
$py = "D:\MyDev\Utai_v2-dev\training\.venv\Scripts\python.exe"

# 自检(先跑这个;它决定后面的读数算不算数)
& $py selfcheck.py

# 把候选臂放到同一把尺子下与参照臂对拍
& $py compare.py --ref arm_raw.wav --shift 6 `
    --cand k0=arm_k0.wav --cand psola=arm_psola.wav `
    --window 396924:458668,910279:972023
```

`--ref` = 逆变换的**输入**(模型在移调位唱出来的那一段);`--window` 缺省 = 全曲。
夹具目录用 `UTAI_RANGE_FIXTURES` 覆盖(缺省 `D:\MyDev\TESTING\s145_range_color\lch`)。

### 出口码(⛔ 三者必须分得开)

| | 含义 |
|---|---|
| **0** | ALL PASS |
| **1** | **读数不符** —— 尺子跑起来了,但量出来的东西不对 |
| **3** | **跑不起来** —— 缺依赖 / 缺夹具 / **夹具指纹不符**。⛔ 不许读成通过,也不许读成「被测的东西不对」 |

「闸自己跑不起来」与「被测的东西不对」报成同一种红,第二次出现一定被耸肩带过(S129 铁律)。

## 三档判据(`selfcheck.py`)

1. **口径闸** —— 尺子的旋钮还是不是登记的那一套。
   ⚠ 它不是「常量等于常量」的空断言:**变异测试实测**,把包络尺的对数轴从 200-9000 改成
   300-6000,**A 档零红**,而真素材上 k0 从 +2.40 漂到 +3.15。
   ⇒「还能量出正确答案」盖不住「口径被人动过」,后者要单独一条判据。
2. **A 档 合成标定**(不需要夹具,永远能跑):用**已知答案**的合成信号量四把尺子。
   ⛔ 合成信号**只用来标定尺子本身**。合成周期信号**系统性冤枉 PSOLA 类算法**
   (S81 被误导三次)⇒ 永远不许拿 A 档去判任何算法的好坏。
3. **B 档 真素材**(需要 S145 夹具):先复现 `predictions`(真值),再复现 `fingerprints`(指纹)。

## 硬规矩(与 `scripts/g2p_rulers/README.md` 的 8 条同源,这里是音频侧的落法)

1. **对照组预注册,并且分成两类**:`predictions` = 与本工装无关就能知道的**真值**
   (κ=1 按代码定义就是纯移调 ⇒ 真值 +6.00 是**免费**的);`fingerprints` = 量出来的**指纹**,
   只回答「有没有从那天漂开」。⛔ **两类不许混着引用。**
2. **取样规则里不许出现被测变量。** 选帧只由**参照臂**的 f0 决定;候选丢掉的浊音
   **不许被静默丢弃**,它在 `浊帧存活` 一栏单独报 —— 一个把高音唱没了的候选会得到
   漂亮的位移读数(S145 的 base f0/4、f0/8 干预臂:残余 +0.20 而浊帧 **8/51**)。
3. **必须与「什么都不做」比。** 阴性对照 raw→raw 就是那条基线,四把尺子各有一条。
4. **对照组必须包含这把尺子最可能出错的那一类。** 包络尺最可能的错法是
   「包络被抹平 ⇒ 位移读成漂亮的 0」⇒ **峰值相关必须与位移一起打印、一起断言**。
5. **登记值必须是量出来的**,而且要和判据的口径逐字对齐(见上面 `NAX` 那一条)。
6. **夹具动过 = 跑不起来,不是读数不符。** 换过夹具的读数与登记值**不构成比较**。
7. **一个绿不代表任何事,除非它红过。** 每加一条判据,配一条变异,并把红在哪一行记下来。
8. ⛔ **仪器不回答「哪个更好听」。** 承重的那一问要过耳朵。
   **凡结论只有耳朵没有仪器,先标【未定】;凡结论只有仪器没有耳朵,承重之前要过一次盲测。**

   ### 8a. 两种问法,两种设计 —— 先分清你在问哪一个(S148 补)

   S145 定的那套协议是为**「有没有可闻差别」**设计的。它对**「哪个更好」**是错的工具:
   「分成两对」这个任务在差别明显时**必然全对**,而它一个字都没说哪一版更好。
   S146g 那次问的是前者(亚样本抖动,~1 dB ΔHNR),做对了;而 S148 的 A/B/C 三条臂
   (拆组 / 改落点深度)**差别是确定可闻的**,问的是后者。

   | | ⑴ 有没有差别(detection) | ⑵ 哪个更好(preference) |
   |---|---|---|
   | 何时用 | 差别可能听不见(工艺改动、ΔHNR ~1 dB 级) | 差别确定可闻,要裁的是取舍 |
   | 每组文件 | **4 个 = 两版各两份**,任务「分成两对」 | **2 个 = 两版各一份**,任务「哪个更好 / 一样」 |
   | 零假设下命中率 | 1/3 | 1/2 **每组** ⇒ 必须**多组**,看一致性 |
   | 空白对照 | 两版逐位相同的一段,发前 assert 最大逐样本差 == 0 | 同一个文件的两份副本,正确答案是**「一样」** |
   | 判读 | 全对 ⇒ 有差别;错一组 ⇒ 该结论作废重来 | 看方向是否一致(k/n)+ 空白对照是否答「一样」 |

   ⛔ **⑵ 里必须允许「一样 / 听不出」这个答案**,而且它是空白对照的**正确**答案 ——
   逼选会把噪声变成信号。
   ⛔ **⑵ 的组数上限是听者的耐心,不是打包成本**:S146 那轮的 R1 组用户**根本没听完**
   (记忆里登记成「未做」,别当成通过)。⇒ 先想清楚怎么把问题压成最少的组。

   ### 8b. 两种都必须遵守的(原 S145 §3)

   * **同场只放两个候选** —— 放第三个会产生顺序/锚定效应,用户实测被它骗过一次。
   * **文件名由【内容 sha1】定序**,不是由标签/组名 —— ⚠ S148 复核发现历史脚本
     `s145_blind.py` / `make_blind.py` 的注释写着「内容哈希」而实际哈希的是**版本标签**与
     **组名**,后果是**同一个组名在下一轮给出逐字相同的答案**(= 复用组名就是泄题)。
     只有 `pack_blind.py` 真的读了文件字节。**照它做。**
   * **KEY 单独一份**,不与素材同目录展示;打包脚本不许把映射打到 stdout。
   * **电平先对齐**,并把对齐用的量与量程写进包里的说明。
     ⛔⛔ **例外是硬的:凡是被测效应【本身表现为电平】的轮次,对齐必须关**(`level_match: "none"`)。
     S148 一场里踩了两次:r3 的 Z2 对齐增益 **−1.194 dB**、r4 的 V3 **−1.964 dB** —— 那两个数
     **就是效应本身**(乘客被放掉 / 陷波被填平),对齐等于把被测的东西减掉再问用户听不听得出。
     ⇒ **规矩:打包器打印实际增益,超过 1 dB 就停下来查它是不是效应本身**,别当成台阶顺手抹平。
   * ⛔ **每一段素材必须真的有人在唱** —— S148 的空白对照第一版切在一段**数字静音**上
     (150-154.5 s),两个文件当然「一样」,而那一组**什么都没验到**。⇒ 打包器现在有一条
     峰值 + 浊帧比例的闸(退 3)。⚠ **它只查整段比例 ≥50%,拦不住尾部静音**:同一场
     V3 段尾还带着 3.5 秒静音照样过闸,是我自己重看波形才发现的。
   * ⛔ **「臂开着」与「臂做了事」是两件事** —— 发出去之前要有一条读数证明候选臂**真的动了**
     (S148 用 `wsola_moved` 打出每遍移动的颗粒数:32810 / 16713 / 37889 / 6781)。
     一个 env 拼错的臂会和参照臂逐位相同,而盲测的答案会是「听不出差别」—— **与「改动无效」同形**。
   * **仪器读数事前写死**在包里的说明里(「仪器那边先说了什么 / 预期是什么」)——
     ⚠ S146g 三个包**一个说明都没有**,那一轮这条没有执行。
